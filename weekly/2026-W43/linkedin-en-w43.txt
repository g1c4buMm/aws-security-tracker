𝗔𝗪𝗦 𝗦𝗲𝗰𝘂𝗿𝗶𝘁𝘆 𝗪𝗲𝗲𝗸𝗹𝘆 | 𝗪𝟰𝟯 (𝗢𝗰𝘁 𝟭𝟵 - 𝟮𝟱, 𝟮𝟬𝟮𝟲)

Amazon Threat Intelligence saw PHP2Shell exploitation in MadPot four days before the CVEs went public. Attackers don't wait for the advisory, so this week comes down to two questions:
1. How fast can we shield what we haven't patched yet?
2. If someone gets in, will we see it, and how far can they move?

AWS shipped 11 security launches and 11 new CVE bulletins this week. Seven items answer these questions directly:

𝗤𝘂𝗲𝘀𝘁𝗶𝗼𝗻 𝟭: 𝘀𝗵𝗶𝗲𝗹𝗱 𝗯𝗲𝗳𝗼𝗿𝗲 𝘆𝗼𝘂 𝗽𝗮𝘁𝗰𝗵
- AWS WAF: the PHP2Shell_BODY rule in the PHP application managed rule group, version 2.4 and later, blocks POST requests used in the attack.
- PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35 fix CVE-2026-109618 and CVE-2026-109619. They do not fix CVE-2026-115560, a separate RCE that only affects apps with session upload progress enabled.
- AWS Continuum for code vulnerabilities is generally available. It builds a context graph of topology, identity and network reachability to rank real business risk, then confirms by testing which findings are exploitable.

𝗤𝘂𝗲𝘀𝘁𝗶𝗼𝗻 𝟮: 𝘀𝗲𝗲 𝘁𝗵𝗲 𝗶𝗻𝘁𝗿𝘂𝗱𝗲𝗿, 𝗹𝗶𝗺𝗶𝘁 𝘁𝗵𝗲 𝗯𝗹𝗮𝘀𝘁 𝗿𝗮𝗱𝗶𝘂𝘀
- GuardDuty Runtime Monitoring adds more than 50 optional detection rules for EC2, EKS and ECS (Fargate included), across 13 finding types mapped to MITRE ATT&CK. Think sudoers changes or audit logging turned off.
- Network Firewall now validates that the destination IP was resolved by your VPC's Route 53 Resolver. Clients can no longer bypass domain rules, filtering extends to SSH and SFTP, and SNI spoofing gets harder.
- IAM Identity Center keeps users, groups, permission set and application assignments when you move the identity source from Active Directory to Okta, Entra ID or the Identity Center directory. No more rebuilding access mid-migration.
- S3 Batch Operations with the new UpdateObjectEncryption API moves objects from SSE-S3 to SSE-KMS in place, with no data movement and without breaking Lifecycle policies.

𝗪𝗵𝗲𝗿𝗲 𝘁𝗼 𝘀𝘁𝗮𝗿𝘁:
1. Patch PHP, confirm your web ACLs use the PHP managed rule group 2.4+, and check whether session upload progress is on.
2. Turn on the GuardDuty Runtime Monitoring optional rules, starting with persistence and defense evasion.
3. Enable Route 53 Resolved IP Validation on Network Firewall for outbound SSH and SFTP.

Also this week: bulletins for the SageMaker Python SDK, Athena engine v3, SAM CLI Terraform hook, AWS MCP Server and Strands Agents; Bedrock Guardrails Standard tier for grounding checks; global condition keys and IsDataPlane in the Service Reference; cross-Region Trusted Identity Propagation for Lake Formation.
